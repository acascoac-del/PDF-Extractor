# Plan: Sistema completo PDF → Excel/Word con extracción inteligente

## Decisiones consolidadas
- **Alcance**: Sistema completo (multiusuario, historial, cola, API, feedback, confianza visual)
- **IA**: Motor híbrido (regex/keywords + LLM OpenAI-compatible)
- **Frontend**: FastAPI + Jinja2 + HTMX + Tailwind
- **Idioma UI**: Español (AR)
- **LLM**: OpenAI-compatible configurable (OPENAI_BASE_URL + OPENAI_API_KEY)
- **DB**: SQLite (vía SQLAlchemy, migrable a Postgres)
- **Docker**: Desde el inicio

## Stack técnico
- **Backend**: Python 3.12, FastAPI, Uvicorn, Pydantic v2, SQLAlchemy 2.x, Alembic
- **Async/Cola**: Celery + Redis (web worker + beat para cleanup)
- **PDF**: `pdfplumber` (texto + tablas), `PyMuPDF/fitz` (render + imágenes), `pymupdf4llm` (markdown para contratos), `pytesseract` + `Pillow` (OCR). Se descarga `spa` para Tesseract en el Dockerfile.
- **Export**: `openpyxl` (Excel), `python-docx` (Word), `csv`/`json` stdlib, `zipfile` para lote.
- **Auth**: JWT (`python-jose`) + bcrypt (`passlib`), API tokens por usuario.
- **LLM**: SDK `openai` con `OPENAI_BASE_URL` configurable (OpenAI/OpenRouter/Ollama/Groq).
- **Frontend**: Jinja2 + HTMX + Tailwind (CDN para empezar), Dropzone, visor PDF nativo del navegador.

## Arquitectura de servicios (docker-compose)
```
web     → FastAPI (uvicorn)  :8000
worker  → Celery worker (procesa PDFs)
beat    → Celery beat (cleanup periódico)
redis   → broker + result backend
```

## Funcionalidades (todas del prompt original)
1. **Carga**: drag&drop + selector, múltiples PDFs, nativos y escaneados (OCR).
2. **Clasificación automática**: reglas + LLM; usuario confirma/corrige antes de procesar.
3. **Extracción factura (prioridad)**: CUIT/CUIL, CAE, tipo A/B/C, razón social, condición IVA, fecha, items (descripción/cantidad/PU/subtotal), impuestos, total, forma de pago. Excel con columnas por campo + hoja consolidada "base de datos" (1 fila por factura).
4. **Otros tipos**: tablas → Excel reconstruido; contratos → Word con títulos/párrafos/negritas.
5. **Validación manual**: vista editable lado a lado (PDF + campos) con HTMX inline; campos con baja confianza resaltados.
6. **Exportación**: `.xlsx`, `.docx`, `.csv`, `.json`, `.zip` en lote.
7. **Historial**: fecha, estado, tipo, re-descarga.
8. **Plantilla AFIP** específica (regex para CAE 14 dígitos, CUIT XX-XXXXXXXX-X, puntos de venta).
9. **Motor híbrido**: regex fijo + LLM para campos variables.
10. **Feedback loop**: correcciones guardadas con valor original + contexto; sugerencias para docs similares.
11. **Confianza visual**: verde/amarillo/rojo por campo (basado en source regex/llm/ocr + score).
12. **Multiusuario + roles**: login JWT, separación por usuario, rol admin/user.
13. **API REST**: `/api/v1/documents`, `/api/v1/extract` con API key por usuario.
14. **Cola**: Celery + Redis, polling de estado vía HTMX.
15. **Seguridad**: archivos fuera del webroot, borrado automático (Celery beat), API tokens.

## Plan de ejecución por fases (orden de implementación)
- **Fase 0 — Setup**: estructura, `requirements.txt`, `Dockerfile`, `docker-compose.yml`, `.env.example`, `config.py`, `README.md`, `.gitignore`.
- **Fase 1 — DB + migraciones**: `database.py`, modelos (user, document, extraction, correction, api_token), Alembic init + migración inicial.
- **Fase 2 — Auth**: registro/login JWT, hashing bcrypt, middleware, separación por usuario, roles, plantillas login/register.
- **Fase 3 — Upload + UI base**: `base.html` con Tailwind + HTMX, dropzone, endpoint upload, detección de escaneado, listado de documentos.
- **Fase 4 — Texto + OCR**: `pdf_text.py` (pdfplumber + PyMuPDF), `ocr.py` (pytesseract con `eng`+`spa`), decisión automática OCR.
- **Fase 5 — Clasificación**: `classification.py` reglas (factura/tabla/contrato/generico) + LLM sugerencia; UI de confirmación.
- **Fase 6 — Rules + LLM core**: `rules.py` (CUIT/CUIL, CAE, fechas AR, montos), `llm.py` (cliente configurable + structured output con Pydantic).
- **Fase 7 — Extractor factura AFIP** (prioridad): `extraction/invoice.py` híbrido; `confidence.py` scoring por campo.
- **Fase 8 — Exportadores**: Excel (detalle + consolidado), Word, CSV, JSON, ZIP en lote.
- **Fase 9 — Vista lado a lado + edición**: detail con PDF + campos editables HTMX, badges de confianza, guardado de correcciones.
- **Fase 10 — Otros extractores**: `table.py` (pdfplumber tables), `contract.py` (PyMuPDF4LLM → docx), `generic.py`.
- **Fase 11 — Celery + Redis + cola**: `celery_app.py`, `pipeline.py` (tarea asíncrona), polling HTMX del estado.
- **Fase 12 — Historial**: página con filtros (fecha/tipo/estado), re-descarga, multi-usuario aislado.
- **Fase 13 — API REST pública**: `/api/v1/*` con API key, doc OpenAPI, ejemplos curl en README.
- **Fase 14 — Seguridad + feedback loop**: `cleanup.py` (Celery beat), borrado tras X días, sugerencias por similitud desde `corrections`.
- **Fase 15 — Tests + docs**: `pytest` con PDFs fixture de muestra (factura, tabla, contrato), README con setup y uso.

## Notas de implementación
- Tesseract actual solo tiene `eng`/`jpn` — en el `Dockerfile` se instalan `tesseract-ocr-spa` o se descarga `spa.traineddata` al volumen tessdata.
- Los PDFs de muestra para tests se generarán sintéticamente (o se pedirá al usuario) para no subir documentos reales.
- El campo `OPENAI_BASE_URL` por defecto apunta a OpenAI; cambiar a `http://localhost:11434/v1` (Ollama) u otro sin tocar código.
- SQLite en `storage/app.db`; para Postgres futuro, solo cambia `DATABASE_URL`.
- Los archivos subidos viven en `storage/` (fuera del webroot), servidos vía endpoint autenticado.
